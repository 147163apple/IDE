## 0. 一句话

**你在右栏随便说；Supervisor 在听、在写方案和 Demo；只有「猜错会改合同范围」才偶尔打断；未确认方案/Demo 前，真写代码的门一直关着。**

---

## 1. 对话里三条轨道（同时存在）

| 轨道 | 你看见什么 | Supervisor 在做什么 |
| --- | --- | --- |
| **A. 自由聊天** | 像 Cursor 右侧：问答、解释、改说法、追问细节 | 听意图、记要点、不立刻动主仓库 |
| **B. 方案 / Demo 起草**（默认主产出） | 中栏逐渐出现：白话方案草稿、可点 Demo | 把对话编译成「要干什么 / 假设了什么 / 可试玩原型」；**0 写主工程** |
| **C. 分叉闸门**（偶尔） | 一张带「推荐」的选择题，或方案草稿里的选项 | **仅当**自我判断：当前歧义会改 Scope / 验收 / 保护边界时才出现 |

铁律：**提案与裁决分离**。Supervisor 只提案；你确认 Demo / 签白话合同；Daemon 才发可写凭证。

---

## 2. 每条用户消息到来时，Supervisor 的内心步骤

1. **归类**：闲聊 / 问现状 / 新愿望 / 改已有方案 / 质疑施工结果。  
2. **范围敏感自检**（「猜错会改合同范围吗？」）：  
   - **否** → 继续聊天，或静默更新方案草稿 / Demo，**不弹卡**。  
   - **是** → 优先把选项写进**方案草稿**；仅当必须当场拍板才出右栏选择题（≤2 轮；带推荐）。  
   - **拿不准** → 按「会改范围」处理（宁问一轮，不静默签错）。  
3. **门禁**：若尚未「确认 Demo」且尚未用户授权合同 → **禁止**派 Coding Worker 写主工程 / Worktree 真改（与 C.11c、`assertDemoConfirmedForWrite` 一致）。  
4. **回复形态**：对人用白话；对机更新意图要点、方案草稿、Demo 沙盒、（仅提案）合同字段。

## 3. 和「像 Cursor」对齐的默认行为

| 场景 | 默认做什么 | 不做什么 |
| --- | --- | --- |
| 一句模糊业务愿望 | 聊清楚 + 起草方案 + 出隔离 Demo | **不**直接开写真代码 |
| 你改口 / 补充一句 | 更新方案与 Demo | 不偷偷扩已签 Scope |
| 你问「现在能不能做」 | 说明差哪步确认 | 不假装已授权 |
| 关键分叉（给谁用、动不动数据、做大做小） | 方案里给 2～3 个推荐选项；必要时右栏一张卡 | 不问 JWT/Redis 开题；不连问超过 2 轮 |
| 你确认 Demo + 签合同之后 | 才派 Worker 在围栏内施工 | 确认前任何「看起来像在写码」只允许发生在 Demo 沙盒 |

**下版倾向（已口头对齐，待立卡）**：把今日 C.11a「聊天里选择题」弱化 → **澄清收进方案草稿选项**；右栏更少打断。

---

## 4. 明确不归右栏对话的事

- 审 Diff、跑四件套、维护大规范正文 → 不是你的活，也不在聊天里考你。  
- 自批合同、自签 Execution、静默放行越界、假绿点亮 → Supervisor **禁止**。  
- 越界、质疑、回灰 → 仍按 C.11d/e：停住问你，不装没事。

---

## 5. 和现有五阶段的关系（对话切片）

对话主要覆盖阶段 **1～3 的「对人」半边**：启发澄清 → Demo → 护照草案；阶段 4～5 在你签字之后才从对话「派工入口」进入，聊天变成进度 / 越界 / 质疑通道，而不是继续自由改 Scope。
