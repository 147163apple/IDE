# P.1 保护清单 · 白话验收核查清单

> 给不看代码的人用。每步都写清楚：终端输什么、页面点哪里、应该看到什么、怎么判断过没过。
> 注意：页面在 **8080**，后台 Daemon 在 **3001**。

## 0. 先启动

终端（在项目目录下）：

```bash
npm run dev -- --port 8080
npm run stagent -- start --repo . --ui-url http://localhost:8080
```

- 浏览器打开 `http://localhost:8080`。
- **过关标准**：页面右上角显示「Daemon 已连接」，顶栏能看到「自由模式 VIBE」。

## 1. 自由模式：改代码全程不弹窗

1. 在右栏对 AI 说：「把首页按钮改成蓝色」（随便一个不碰锁的改动）。
2. **过关标准**：不出现任何「同意吗」卡片；顶栏仍显示「自由模式」。
3. 如果项目里扫出了「登录」「支付」之类的目录，会先出现一张**推荐卡**——这是首次导入的建议，不是拦截。点「以后再说」即可，之后不再打扰。

## 2. 撤销本轮：手改也会被撤

1. 让 AI 改一个文件；改完后**你自己**在中间编辑器里手动改另一个文件并保存。
2. 点顶栏「↶ 撤销本轮改动」。
3. 弹窗必须写明：「这期间你自己手动改的部分也会一起撤销」。
4. 点确定。
5. **过关标准**：AI 改的、你手改的都回到本轮开始前；本轮新建的文件消失。页面出现绿条「已回到本轮开始前…」。

## 3. 推荐卡与锁定（保护清单）

1. 换一个带 `auth` / `login` / `payment` 目录（或有 `.env`）的项目打开。
2. 应弹出「建议锁住这些重要部分」，列出「登录」「支付」「密码和密钥」。
3. 点「锁定选中的部分」。
4. **过关标准**：顶栏从「自由模式」变成「保护模式 PROTECTED」；左栏不出现让你手写路径的输入框（本卡不做手写规则）。

## 4. 碰锁：一张卡、最多两次交互

1. 让 AI 改一个被锁住的文件（例如 `src/auth/login.ts`）。
2. **过关标准**：
   - 弹**一张**卡，列出这轮要碰的锁住文件；不是每个文件弹一次。
   - AI 被拦在原地，文件没有被改。
3. 点「同意」→ AI 继续，本轮这些文件不再问。
4. 若 AI 又要改**清单外**的另一个锁住文件 → 再弹一张「补充卡」；这仍算同一次授权的补充。
5. 点「不同意」→ 文件一点没动，AI 收到「换方案」的提示。
6. **怎么判断过没过**：整个过程你只点了「同意/不同意」+ 最后「合并」，没有第三个确认框。

## 5. 断线/重启：卡片还在，绝不自动放行

1. 让 AI 碰锁，等卡片出现。
2. 直接关掉浏览器页面（或停掉 Daemon 再启动）。
3. 重新打开页面 / 重连。
4. **过关标准**：卡片还在，文件仍然没被改。不会因为你走开就自动同意。

## 6. 门卫出错：一律拦截

- 这条由自动化测试证明（见第 9 节），页面上不用手动试。
- 原理：清单文件损坏、读不出来、超时，全部按「拒绝」处理，不会放行。

## 7. 顺手修：断线徽章变暗

1. 停掉 Daemon（终端 Ctrl+C）。
2. **过关标准**：右上角原来绿色的「GATEWAY_ENFORCED 受控」变成灰色的「未连上后台 · 受控状态未知」。
3. 重新启动 Daemon，徽章恢复绿色。

## 8. 顺手修：顶栏显示真实分支

1. 终端执行 `git switch -c 测试分支`（或切到任意分支）。
2. 刷新页面。
3. **过关标准**：顶栏「分支：」显示你刚切的分支名，不再永远是 main。
4. 验完切回：`git switch feat/p1-protection-list`。
