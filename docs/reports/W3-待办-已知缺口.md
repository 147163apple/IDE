## 4. 事实核对发现（性能 / 生命周期，待后续版本处理）

> 来源：2026-10-21 事实核对附录。以下仅为问题登记，**本轮不改业务代码**，也不属于 W.4 门禁范围。

### 4.1 `claude-code-adapter` 崩溃时 `tmpRoot` 临时目录 GC 缺口

- 现象：适配器在运行中崩溃/被强杀时，`stagent-claude-*` 临时目录可能残留，缺少启动期或退出期的兜底清理；
- 影响：长期运行会累积磁盘占用，并可能干扰后续会话的临时目录枚举；
- 方向：在 daemon 启动自愈或适配器 `run()` 的 `finally` 中按前缀 + 超时清理，并登记清理结果；
- 状态：[ ] 未修复（待后续版本立项）。

### 4.2 `src/routes/index.tsx` 连接 WS 时无条件触发 `/api/arch/graph` 全仓同步 AST 计算

- 现象：页面建立 WebSocket 连接即请求全仓架构图，服务端同步计算 AST，主线程可能被长任务阻塞；
- 背景：`TASK-B.1`（本地 AST 增量依赖图）已 **DEFERRED → v0.2+**，当前调用属实现漂移；
- 影响：大仓库首屏/重连时出现可感知卡顿，且与 B.1 的增量能力缺失叠加；
- 方向：短期改为按需/空闲触发并加超时与缓存；长期随 B.1 增量引擎落地；
- 状态：[ ] 未修复（待 B.1 或独立性能卡处理）。

**验收判据（PASS / FAIL，量化）**

1. **主线程单次同步计算 ≤ 50ms**
   - PASS：Daemon 主线程在请求处理路径上的任意单次同步计算耗时 ≤ 50ms（以 `performance.now()` 包裹 `buildDependencyGraph` 等同步段实测，取 P100，不以平均值代替）；
   - FAIL：出现任一次 > 50ms 的同步计算，或无法提供可复现的测量记录。
2. **`/api/arch/graph` 增量缓存 + G-16 路径收敛**
   - PASS：接口具备基于文件 `mtime` 的增量缓存（命中缓存不重复解析未变更文件），且扫描路径严格收敛至 `src/**`（G-16 前缀白名单，越界路径 0 条）；
   - FAIL：每次请求全量重算、无 `mtime` 失效判断，或扫描范围包含 `src/**` 之外的文件。
3. **前端建连不再自动触发**
   - PASS：UI 建立 WebSocket 连接后 30 秒内，`/api/arch/graph` 请求计数**严格为 0**（回归断言以请求计数为准，不以「是否有 loading」代替）；
   - FAIL：建连后 30 秒内出现任意一次 `/api/arch/graph` 请求。

### 4.3 `splitShellSegments` 朴素正则的引号边界盲区

- 现象：`sh -c` 解析采用「正则拆 `; && || |` + 空白分词」，不解析引号与转义；
  - `sh -c 'echo "a; sudo ls"'` 会把引号内的 `;` 当命令分隔符（偏保守，可能误报）；
  - `sh -c 'su""do ls'` 这类跨引号拼接会被拆成 `su` / `do`，存在理论漏判。
- 影响：威胁守卫对刻意构造的 shell 拼接可能漏判；当前仅作为纵深防御的一层，
  仍依赖 Gateway 白名单与参数策略兜底。
- 方向：引入轻量 shell tokenizer（处理单/双引号、反斜杠、`$()`/反引号至少拒绝），
  或在解析失败/含引号时一律按「不可判定」拒绝；
- 状态：[ ] 未修复（登记为已知边界，后续安全卡处理）。

### 4.4 N-1：前端 `fetchProtection` 3s 硬编码常驻轮询

- 现象：前端 `fetchProtection` 以硬编码 `3000ms` 常驻轮询保护状态，页面隐藏、无活跃合同、清单未变化时仍持续请求；
- 影响：后台标签页持续占用 CPU/网络与 daemon 请求配额，移动端/多标签场景放大；
- 改造原则：
  1. **页面可见性感知**：`document.hidden === true` 时立即暂停轮询定时器；切回前台（`visibilitychange` → visible）时补偿刷新一次，再恢复定时器；
  2. **空闲自适应降频**：无活跃合同且保护清单未变更时，自适应降频至 **≥ 60s**；有新合同/清单变更事件时立即提升回原频率；
  3. **WebSocket 状态帧不受影响**：保持现有 WS 状态帧处理完好，待审批卡等关键事件仍必须秒级推送，不得因轮询降频而延迟。
- 验收判据（PASS / FAIL）：
  - PASS：`document.hidden=true` 后 5s 内 `fetchProtection` 请求计数为 0；恢复可见后 1s 内恰好补偿 1 次；
  - PASS：无活跃合同且清单未变更的 3 分钟内，请求间隔实测 ≥ 60s；
  - PASS：WS 关键状态帧（含待审批卡）从服务端发出到 UI 呈现 ≤ 1s；
  - FAIL：隐藏页仍有轮询、空闲间隔 < 60s，或关键事件改由轮询承载导致延迟 > 1s。
- 状态：[ ] 未修复（待 N-1 性能卡处理）。
