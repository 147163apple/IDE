# ADR-0009: 任务 Graph 串行拓扑与变更指纹点亮机制

> **状态**: ACCEPTED
> **基线**: 架构规范 v1.5.1 新增；抽出时基线 v1.6.1（commit `4280de6`，2026-10-24）
> **源自**: 《系统架构设计规范》§8 ADR-009 `[v1.5.1 新增]`
> **相关**: ADR-0005（确定性验证）、ADR-0002（单工作区互斥）
> **实现**: `TASK-C.7` / `S.6` / `C.10o` / `C.10p`

## 背景

早期设计是「每个 Graph 节点生成一个独立 Git Commit，用该 Commit 作为点亮依据」。这在两种情况下会崩溃（登记为 P-09）：

1. **Squash Merge 会让节点 SHA 成为悬空对象**——合并后所有节点 Commit 都不再可达，追溯链整体断裂；
2. **全量增量编译在前端技术栈不现实**——每节点独立构建的成本不可接受。

同时，v0.1 需要在「非技术用户能看懂进度」与「不引入多任务并发的复杂度」之间取舍。

## 决策

1. **放弃节点级 Git Commit 要求**。节点点亮改由三项确定性物理证据共同决定（缺一不可）：
   - 目标文件已成功写入本轮 Worktree；
   - 关联的验证命令子集（`applies_to_node_ids`）执行完成且退出码为 0；
   - Daemon **现场计算**并持久化该节点的变更集指纹（`node_patch_fingerprint`）。
2. **Squash Merge 时把全量节点指纹归一化嵌入 Git Trailer** 归档，使「节点↔最终提交」的关联在合并后依然成立。
3. **v0.1 DAG 严格按拓扑序串行执行，并发度 = 1。** 并行隔离能力推迟到 v0.2+（见 v0.2 RFC §5）。

## 后果

**正面**：点亮获得与 Git 历史解耦的物理定义；Squash Merge 的整洁性与可追溯性同时保住。

**代价与约束**：
- 「两个 Worker 同时干活」在 v0.1 不可达，大任务只能靠微合同拆步来提升感知速度；
- 指纹必须现场算：任何允许前端传入指纹的口子都会让 ADR-0005 的确定性保证失效；
- 合并清理 Worktree 后再次核销需先重建，`TASK-C.10p` 为此引入自动 ensure/重建，**但重建树不得自动点亮**。
