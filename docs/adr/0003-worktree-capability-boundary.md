# ADR-0003: 诚实承认 Worktree 的能力边界

> **状态**: ACCEPTED
> **基线**: 架构规范 v1.6.1（commit `4280de6`，2026-10-24）
> **源自**: 《系统架构设计规范》§8 ADR-003
> **相关**: ADR-0008（Demo 独立 Origin）、ADR-0013（CLI 隔离）、`daemon/baseline/os-sandbox.ts`

## 背景

Git Worktree 常被误认为「沙盒」。事实是：

- Worktree **只提供**文件系统维度（独立工作目录）与分支维度（独立 HEAD）的隔离；
- 它**不提供**任何操作系统级进程隔离、网络隔离或权限降级。在 Worktree 里运行的 Worker 进程，拥有与宿主用户完全相同的 syscall 能力、网络出口与凭据读取权。

如果在对外表述或内部实现里把 Worktree 当沙盒，会造成**虚假的安全承诺**——这比没有隔离更危险，因为它会让人据此放松其他防线。

## 决策

1. **规范口径诚实化**：Worktree = 文件系统与分支隔离，**不是** OS 级沙盒。任何对外文档、README、发布说明**不得**宣传为「具备操作系统级安全容器」。
2. **纵深由其他机制补齐**，而非由 Worktree 承担：
   - 受控 Gateway 拦截文件路径与越界写入；
   - 环境变量脱敏与环境白名单（见 ADR-0013）；
   - 只读 / 断网证明由独立沙盒机制给出（`daemon/baseline/os-sandbox.ts`，Darwin `sandbox-exec` / Linux `unshare -n`）。
3. **未证明即不得升格承诺**：当 OS 沙盒在当前平台不可应用时，`logical_fallback` 必须显式写明「本轮不构成只读/断网证明」，**严禁**把扫描结果写成「绝不触碰线上业务」。

## 后果

**正面**：避免了「沙盒」一词带来的合规与信任风险；`TASK-C.14e` / `TASK-C.14c` 能够据此把 OS 只读证明做成独立可测的能力。

**代价与约束**：
- 每一次涉及「只读」「断网」「绝不触碰」的文案都必须回溯到具体机制是否有孪生的测试证明，文案成本显著上升；
- 2026-10-27 在 Supervisor v2.0.2 验证过程中真实暴露过一类缺陷：`proveScanNetworkDenied` 曾以 `code !== "CONNECTED"` 判定，导致沙盒启动失败（`code === null`）被误算成「断网已证明」，会凭空生成一条假证据。修复见 [`../specs/supervisor.md`](../specs/supervisor.md) §10.5。这条缺陷的价值高于任何一次断言失败——它属于**证据可以凭空生成**这一类别。
