# ADR-0008: Demo 原型预览服务独立 Origin 与 iframe sandbox 隔离架构

> **状态**: ACCEPTED
> **基线**: 架构规范 v1.5.1 新增；抽出时基线 v1.6.1（commit `4280de6`，2026-10-24）
> **源自**: 《系统架构设计规范》§8 ADR-008 `[v1.5.1 新增]`
> **相关**: ADR-0003（能力边界）、架构规范 §4.4 / §11 注记 8
> **实现**: `TASK-D.1` / `D.1b` / `D.1d`

## 背景

v1.5.0 引入中栏 Demo 原型视口后，出现一条高危攻击面（登记为 P-16）：

> **若 Demo 与 IDE 控制台同源执行，模型生成的 JS 将能够直连 loopback 上的 Daemon API。**

后果是灾难性的：用户在中栏「试玩一个假页面」的动作，等价于把自己的本机写权限、Token 与全部项目文件交给了一段由模型生成的脚本。同源会让浏览器的同源策略保护完全失效。

## 决策

四条同时生效，缺一不可：

1. **Demo 视口强制 `iframe sandbox="allow-scripts"`**，**坚决不给 `allow-same-origin`**——这是本决策的核心，一旦放开即等于取消整个 ADR。
2. **Daemon 在独立随机端口（如 4100~4110）启动预览服务**，与主 Daemon 端口（3001~3010 段）物理分离。
3. **响应头注入严格 CSP**，阻断 Demo 页面发起任何指向 Daemon 端口的连接。
4. **Daemon 校验 Origin 标头**，拒绝来自预览端口的任何 API 请求。

**诚实声明**：Demo 视口是静态跨源展示，**不宣称**拥有操作系统级沙盒与网络隔离能力（对齐 ADR-0003）。

## 后果

**正面**：把「试玩原型」从最高危动作降为安全动作；非技术用户可以自由点击而不必理解 Origin / CSP。

**代价与约束**：
- 控制台与 Daemon **可以**同源托管（`TASK-D.1b`/`D.1d` 方向，便于 `stagent open` 少开终端、自动带 `#token=`）——但这**仅影响 who serves HTML/JS，不降级鉴权，也不构成 Demo 可同源的理由**。二者的区别已在架构规范 §11 注记 8 显式写出。
- 后续所有涉及「打开项目 / 工作台托管」的任务卡都必须重申本条不被动摇，形成了一条长期的呈现纪律约束。
