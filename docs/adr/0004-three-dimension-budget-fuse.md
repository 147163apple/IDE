# ADR-0004: 不可绕过的三维预算熔断

> **状态**: ACCEPTED
> **基线**: 架构规范 v1.6.1（commit `4280de6`，2026-10-24）
> **源自**: 《系统架构设计规范》§8 ADR-004
> **相关**: ADR-0005（确定性验证）、`daemon` 预算(service) 与 admission 判定

## 背景

LLM Agent 的失效模式之一是**无界循环**：反复重试同一个失败的验证命令、在多个文件间来回沖突修改、把整个预算烧在一次注定失败的实现上。若预算只由 Prompt 声明（「你最多试 3 次」），则它不构成任何系统约束——它是修辞。

同时，「预算」若只有一个维度（如仅限制 Token），Agent 会用工具调用或 CLI 子进程轻松绕过。

## 决策

三维硬限额必须同时存在、在 Daemon 侧确定性记账、**重启与改名不得重置计数**：

| 维度 | 内容 | 越限行为 |
| :--- | :--- | :--- |
| **Token** | 单次产生本轮的累计模型消耗 | 熔断并转入 PAUSED，向用户呈现事实，等待拍板 |
| **工具调用次数** | Worker 的写/执行类工具累计调用 | 同上 |
| **测试重试次数** | 同一 `assertion_id` 的重跑次数（`max_verification_retries`） | 计入返工超限，达阈 → `ESCALATED_HUMAN` |

补充三条：

1. **重启不重置**：预算计数持久化在 `.stagent/` 侧车，进程重启 / Worktree 重建 / 会话改名均不得使其归零；
2. **预算上调必须重新审批**：任何提高配额的动作等同签署一份新微合同，**禁止** Agent 自行上调，禁止「默认足量」；
3. **返工期禁追加断言**：已达重试试用额度后，不得偷偷新增验收条件来「重新获得」重试预算。

## 后果

**正面**：把「烧完一晚预算改同一个 bug」这一类失控变为不可能；用户对费用与时间有可预期的上界。

**代价与约束**：
- 计数持久化引入了跨版本兼容义务，任何数据模型升级迁移都不得丢失已有计数；
- 三维预算需要在 admission（准入）阶段即被评估，因此 admission 必须是纯确定性计算，不得调用模型。
