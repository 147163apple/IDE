# ADR-0006: 本地优先与非防篡改声明

> **状态**: ACCEPTED
> **基线**: 架构规范 v1.6.1（commit `4280de6`，2026-10-24）
> **源自**: 《系统架构设计规范》§8 ADR-006
> **相关**: ADR-0003（能力边界）、ADR-0011（审计侧车）、[`../rfc/v0.2-multi-agent-pipeline.md`](../rfc/v0.2-multi-agent-pipeline.md) §7.2 三级信任模型

## 背景

Stagent 的全部状态（合同、快照、证据、审计日志）都存放在用户本机 `.stagent/` 目录下的普通 JSON / Text 文件中。这带来两个必须坦白面对的事实：

1. **这些文件拥有与用户相同的写权限**。持有本机写权限的任何进程（包括恶意脚本）都能改写它们。
2. 因此它们**不构成密码学意义上的不可篡改**。

反过来，若为了「防篡改」引入签名密钥托管、远端时间戳、云端存证，就会立刻违背 MVP 阶段的核心取向：**本地优先、零依赖、零外传**。

## 决策

1. **坚持 Local-First**：状态存储于本地 `.stagent/` 目录，不引入必需的网络依赖，不把用户的代码与意图上传到任何远端。
2. **公开承认非防篡改**：所有对外论述、README、发布说明必须明确——本地未签名 JSON **足以支撑单机可信审计，但不构成密码学防篡改**，无法抵御持有宿主写权限的攻击者。
3. **禁止升格措辞**：哈希 / 指纹 / Evidence 一律表述为「一致性校验（verifiability）」，**禁止**写成「防篡改」「不可伪造」「签名」。

## 后果

**正面**：
- 诚实边界成为可被引用的一致性基线，多份文档（`v0.2 RFC` §7.3.4、`开发任务规范`、Supervisor SSOT §4.5）据此统一口径，避免相互打架；
- 用户获得零网络依赖的安装与使用体验。

**代价与约束**：
- 任何涉及「证据可靠」的话术都需要带限定词，营销/对外文案成本上升；
- 必须防住一类实现缺陷：让 Worker 直接写入 Evidence 哈希或结论字段并被采信。Worker 写入的哈希**仅可作索引用途**，结论一律由 ADR-0005 要求的独立校验器重算；这在 v0.2 提案中被明确为「禁止轻信 Worker 写入的任何哈希或结论字段」（见 v0.2 RFC §7.3.4）。
