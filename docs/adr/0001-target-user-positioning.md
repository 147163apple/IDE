# ADR-0001: 目标用户定位演进与分层适配

> **状态**: ACCEPTED
> **基线**: 架构规范 v1.5.1 更新版；抽出时基线为 v1.6.1（commit `4280de6`，2026-10-24）
> **源自**: 《系统架构设计规范》§8 ADR-001 `[v1.5.1 更新]`
> **相关**: ADR-0007（双 Agent 分权）、[`../specs/system-architecture.md`](../specs/system-architecture.md) §0.1

## 背景

Stagent v0.1 起初定位于**独立开发者与外包工程师**——他们看得懂 Diff、跑得了终端、维护得了两份大规范。

但随着自然语言交互与可视化界面的成熟，出现了一类**强烈但无法自行接入**的诉求：非技术业务用户。他们能说清「想要什么」，但无法：
- 理解 Git Worktree / 分支 / 合并的语义；
- 判断一份 Diff 是否越过了本轮边界；
- 用工程语言描述验收标准。

若维持单一开发者定位，产品天花板被锁死；若全面转向非技术用户，又会牺牲底层强隔离与确定性门禁——这是项目的立身之本。

## 决策

**保留底层强隔离与防越权控制面完全不变；在上层追加面向非技术用户的适配层。**

具体三条：

1. **上层**提供「八步旅程」「Demo-First 原型先行」「白话 15 状态映射」，把 Git / Sandbox / 哈希 / 锁文件全部沉到水面下；
2. **Supervisor 担任翻译器**：自然语言 ⇄ 工程契约，对上用白话选项卡与 Demo，对下用 Scope / 证据 / 有限回打；
3. **底层**（Daemon / Gateway / Worktree / Evidence）**一行不改**——非技术体验只能叠加在门锁之上，不能用削弱门锁换取。

## 后果

**正面**：产品可用人群显著扩大；「界面友好」与「安全兜底」解耦为两条独立演进线。

**代价与约束**：
- Supervisor 承担了极重的语义压缩责任，任何 UI 文案都必须能被回溯到一条机器可验证的契约条目；
- **单向约束**：白话体验**不得反向要求底层放宽门禁**。例如「别再弹那张卡了」不得被实现为「静默放行」，只能在卡片呈现层做合并（多文件合成一张卡）或降级话术；底层门禁是否存在、何时触发，一律由 Daemon 决定，不由 UX 偏好决定。
- 后续所有 UX 打磨任务卡（C.8～C.16 系列）均须显式声明「不改变鉴权 / Demo Origin / 点亮三证」，正是本决策留下的纪律成本。
