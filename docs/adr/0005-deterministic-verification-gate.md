# ADR-0005: 确定性验证门禁与 Evidence 绑定候选 SHA

> **状态**: ACCEPTED
> **基线**: 架构规范 v1.6.1（commit `4280de6`，2026-10-24）
> **源自**: 《系统架构设计规范》§8 ADR-005
> **相关**: ADR-0004（预算熔断）、ADR-0009（指纹点亮）、ADR-0006（非防篡改）

## 背景

「AI 说自己完成了」是本项目最需要根除的一类假信号。若允许以下任何一种，整个产品的可信度即归零：

- 模型为自己写的测试打勾；
- 前端根据 Worker 返回的布尔字段点亮节点；
- 「跑了测试」但结果未与实际被验证的那份代码绑定。

此外探索过一个已废弃的方案：为每个 Graph 节点生成独立 Git Commit 以便追溯。它与最终采用的 Squash Merge 直接冲突——squash 会令节点 SHA 成为悬空对象，追溯链断裂（详见 ADR-0009）。

## 决策

1. **`can_merge` 与任何验收结论只能由 Daemon 依据真实进程退出码派生。** 模型对 `can_merge` 无任何设定权；Worker 自报的通过/失败仅作为索引用途，结论必须由独立校验器重算。
2. **Evidence 必须强绑定候选内容**：绑定候选 Commit SHA（若存在）与变更集 / tree 内容指纹；任一项与实际被验证对象不一致，该 Evidence 立即失效。
3. **空验证集禁止点亮**：当节点关联的验证命令集合为空时，不得进入 ILLUMINATED（对应 `E_EMPTY_VERIFICATION_BLOCKED`），从机制上消灭「空检查假绿」。
4. **失败/SKIP 不得计为通过**：`FAIL` / `BLOCKED` / `NOT RUN` / `SKIPPED` 必须如实记录，不得被折叠为「部分通过」。

> **注**：`manual_confirmation` 人工确认记录为 `can_merge` 的前置必要条件（合同声明 `manual_confirmation` 时，确认记录不齐全则 `can_merge=false`），不构成退出码派生规则之外的第二种派生源。本 ADR 决策不变。

## 后果

**正面**：点亮与合并获得了一个不依赖诚实性的物理定义，这是「非技术用户看灯判断进度」能成立的前提。

**代价与约束**：
- 所有 Worker 适配器都必须把控制权交还 Daemon 跑验证；自行声称「我验证过了」的适配器不得被记为 `GATEWAY_ENFORCED`；
- 候选指纹重算带来额外 IO 成本，`TASK-C.14f` / `task-c17` 曾出现 IPC 等待预算过紧导致的性能类抖动，最终通过「延迟断言改相对测量」处置（见 [`../specs/supervisor.md`](../specs/supervisor.md) §10.4）。**这是测试基建问题，不是本 ADR 的缺陷**。
- 严格绑定 SHA 意味着任何 rebase / amend 都会让Evidence 失效并要求重跑，这是蓄意的保守设计。
