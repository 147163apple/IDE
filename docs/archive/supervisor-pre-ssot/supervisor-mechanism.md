## 0. 一句话结论

**右侧两条入口，背后一个监理大脑。**  
需求 Agent 只帮用户把散乱想法说清楚；Coding Worker 只在围栏里写码自测；**其余全归 Supervisor**——但对上用白话选择题与 Demo，对下用 Scope / 证据 / 有限回打，对系统**绝不自批、绝不自写主干**。Daemon / Gateway 才是裁决与拦截。

今天 Supervisor 先扛住**安全下限**（围栏、证据、隔离再合并）；**商业上限**（改得对业务、圈得准、测得深）仍依赖后续能力，尤其 Impact Analysis = **v0.2+**（见合同说明 §7.3.5 / §7.5）。

## 1. 角色边界（写死）

| 角色 | 做什么 | 绝不做什么 |
| --- | --- | --- |
| **用户** | 提想法、点选项、试 Demo、签白话卡、看点亮、真机验收 / 回滚 | 不审 Diff、不跑四件套、不维护两份大规范 |
| **需求 Agent** | 对话壳：收模糊话、出选项卡、记要点 | **不写项目代码、不签授权、不点亮图谱、不扩 Scope** |
| **Coding Worker** | 领一张卡，在 Worktree + Scope 内改代码 + 自测 | **不聊产品、不扩 Scope、不合主干、不宣称「已完成」即点亮** |
| **Supervisor** | 澄清策略、触发 Demo、草拟护照、拆灰图、派工、红队质询、证据提案、验收引导 | **不自批合同、不自签 Execution、不直接写主干、不静默放行未核销节点** |
| **Daemon / Gateway** | 校验 Schema、发/拒凭证、拦越界、跑门禁、核指纹、合入 / Abort | 不做产品决策；不替用户点「确认开工」 |

**铁律**：提案与裁决分离。Supervisor 只提案；用户签字；Daemon 发凭证并拦截。

## 2. 四机制（用户侧价值）

### 2.1 技术问题 → 业务场景选择题

- 不问 JWT / Redis；问「按累计消费升级还是付费订阅？」，并给 **2～3 个带推荐标签的选项卡**。  
- 主动补边界死角（降级、退款是否扣减等），用业界安全默认值填非核心细节，并在合同里写明。  
- 澄清轮次宜短（目标 ≤2 轮）；大欲望主动建议切成微步（见 2.4）。

### 2.2 伴生隔离 Demo 感官对齐

- 需求七八成时，在**隔离沙盒**拼静态 / Mock 原型，**签署前对主工程 0 字节写入**。  
- 用户试玩再往下；沟通偏差尽量消灭在动真码之前。  
- Demo ≠ 交付：满意后才进入护照草拟。

### 2.3 自动化隐形护栏（高质量的幕后责任）

- **Scope / P.1**：可写路径 + 保护名单；越界由 Gateway 拦（`E_OUT_OF_SCOPE` / 保护否决）。  
- **弱测 / 回归自查**：Worker「说完成」不够；查空断言、假绿、既有回归（底座半有，强制条款仍在补——合同说明 §7.3 #1/#2）。  
- **证据点亮**：退出码、指纹、Evidence 核销后才向 Daemon **提案**点亮；用户只看人话进展，不见技术报告墙。

### 2.4 微步合同（Micro-Contracts）切蛋糕

- 大欲望拆成半小时级小护照：先基础等级与折扣，再积分商城……  
- 每步一张白话授权卡（交付目标 / 改哪些 / 怎么验）→ 真机预览 → 一键验收或回滚。  
- 节奏由 Supervisor 建议，**拍板永远在用户**。

## 3. 五阶段流水线（输入 / 决策 / 产出）

> 对人极简、对机极严：每阶段都同时有**白话**与**硬产物**。

| 阶段 | 输入 | Supervisor 决策 | 对人（白话） | 对机（硬产物） |
| --- | --- | --- | --- | --- |
| **1. 意图启发与业务澄清** | 模糊自然语言；项目只读元数据；行业建议库 | 意图分类；Mode 轻量 vs 标准合同；分歧→选项卡；是否拆微步 | 选择题 + 推荐理由；「先做哪一步」建议 | 结构化意图要点；未决项清单；需求断言 **DRAFT** |
| **2. 只读探索与 Mock** | 阶段 1 已确认规则；只读探活（**对接目标**，见 §5） | 复用度；原型关键状态；是否过「可编码」门禁 | 预览入口：「拖一下看是不是这个感觉」 | 隔离 Mock / Demo Origin；试玩反馈记录；**仍 0 写主工程** |
| **3. 影响收敛与合同草案** | Demo 认可；保护名单；仓库现状 | 收敛 writable；排除敏感区；验收集；白话翻译；爆炸过大则再拆步 | 白话授权卡：改什么 / 不碰什么 / 怎么验 | Contract **提案**（非已批）；`writable_paths` + 保护声明；需求断言 **PROPOSED**；TaskGraph / DAG **草案** |
| **4. 实施编排与红队质询** | Daemon 生效合同 + 执行许可（**对接目标名**见 §5）；Worktree；Worker 补丁与日志 | 派单粒度；越界挂起；红队挑刺；有限回打；扩 Scope 必回用户 | 失败说人话；需要扩权时弹出新卡 | Worker 任务指令；质询报告；返工指令；**点亮提案**（非自点亮） |
| **5. 证据核销与辅助验收** | 候选 Tree；测试日志；冻结断言 | 断言↔Evidence 对齐；真机是否可验；合并 / Abort 引导 | 「请在第 5 屏看这两处」；一键合并或放弃 | Evidence Bundle（绑 Tree SHA）；验收卡；归档 / 合并提案给 Daemon |

```
[阶段1 澄清] → [阶段2 Demo] → [阶段3 护照草案] → [用户签字]
       → [Daemon 生效] → [阶段4 派工+红队] → [阶段5 证据+验收] → [合并或 Abort]
```

## 4. 角色模型（比喻）

- **用户 = 投资人 / 甲方**：提想法、试玩、拍板、终验。  
- **Coding Worker = 车间操作工**：工位内拧螺丝，越界被网关拦。  
- **Supervisor = 项目总监**：  
  - **对用户（情商高）**：选项、Demo、切步、屏蔽术语；  
  - **对 Worker（手腕硬）**：最小 Scope、清晰上下文、拿放大镜挑刺，没证据不收工；  
  - **对系统（守规矩）**：不违规写主干，越权老实向 Daemon 申请，证据进不可偷懒的核销链。

## 5. 必须收紧（禁止写成「已全实现」）

### 5.1 Impact Analysis（目标约束 ≠ v0.1 已交付）

**目标约束**（立卡落地时遵守，蓝图见合同说明 §7.3.5）：

- 依赖追踪默认 ≤ **2 hop**；  
- `writable_paths` 默认宜 ≤ **~5** 个文件，过大则拆微步；  
- **禁通配符** `*` / `**`（须明确相对路径）；  
- P.1 / 保护名单 **一票否决**敏感区。

**诚实口径（本定稿强制）**：

| 可说 | 不可说 |
| --- | --- |
| v0.1 **可降级**为保守 Scope（规则/关键词拟定）+ P.1 拦截补漏 | 「今天已按 AST 依赖图精准自动圈 Scope」 |
| 完整 AST / 路由双向遍历 = **v0.2+** | 把 §7.3.5 蓝图写成已交付 |

对账：合同说明 **§7.5 表行 #7 = 未实现**。

### 5.2 红队质询（纠正「60s 超时默认放行」）

| 规则 | 定稿 |
| --- | --- |
| 回打回 | **有限次**（达上限停止空转） |
| 反复失败 | **必须回用户**，说明人话原因 |
| 需扩 Scope | **必须新白话卡 + 用户重签**；禁止静默扩权 |
| 超时 | **不静默放行**：暂停或标黄 + 写审计；置信度未红也不得当绿灯 |

审查维度仍包括：断言真伪、既有回归、未跟踪文件是否进 Scope（与 Gateway / 未跟踪门禁对齐）。底座「半有」、强制条款「待立卡」——见合同说明 §7.3 #1/#2、§7.5 #6。

### 5.3 接口名与事件名（对接目标 ≠ 代码现状）

下文出现的 `lease.readonly`、`ExecutionToken`、`DEMO_PREVIEW_STATUS`、`ContractProposal`、`DisputeReport` 等，一律视为**对接目标 / 讨论稿名词**。  
是否已有等价 HTTP / IPC，以合同说明 **§7.5** 与现网 `POST /api/...`、Gateway 行为为准；**本定稿不暗示新 IPC 已落地**。

### 5.4 安全下限 vs 商业上限

与合同说明导言、§7.4 对齐：

- **下限（Supervisor + Daemon 今天主责）**：不瞎写主干、不碰保护地基、不假绿点亮、半成品不合主线。  
- **上限（未保证）**：Impact 圈准、弱测挡死、对抗式 QA、商业一次做对——靠后续立卡与用户小步验证，不装成「点两下变独角兽」。

## 8. 收口三句

1. Supervisor = **懂业务的翻译官 + 守纪律的交付总监**，不是传话筒，也不是可自批自写的超级模型。  
2. 用户只做：聊 → 玩 → 签 → 看点亮 → 试真机；工程严谨性在 Supervisor 提案与 Daemon 裁决背后。  
3. 思考已定稿于本文；**砌进代码仍须一张张工程卡**——按兵不动的是宪法全文，不是「永不实现」。
