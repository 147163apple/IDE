# 非技术用户旅程验收稿（白话定稿 v1）

> 给谁看：只关心「看得见、点得到」的非开发者（产品验收）。  
> 依据：Tina 口述八步循环 + 架构规范 v1.6.1 §0.2 / §0.2.3；对照任务规范 v1.6.2 已合入能力与 2026-10-24 走查。  
> 标注：`现状已有` = 本机现在大致能摸到；`缺口` = 体验上还缺，不能当已验收。  
> 术语对照（正文尽量少用）：Supervisor = 幕后总包工程师；Worker = 真正改代码的施工员；Demo = 静态假页面预览；Graph / 任务图 = 功能拆解与点亮图；合同 = 本轮授权说明书；保护 = 登录/支付等锁住的地方。

---

## 0. 一句话说清目标体验

> **进门（打开项目）**：八步之前先要能稳定打开工作台。愿景是「像 Cursor 一样 Import / 最近打开，与聊天同壳」；现状与已知空白壳缺陷见 `docs/archive/open-project-vision-and-status.md`，修复卡 `TASK-D.1d`（桌面真·选夹 `TASK-D.1e` 可延后）。下文八步默认你已经进到可聊的工作台。


**你只跟右侧聊天。** 想清楚了先看假页面（Demo）；满意再开工。中间能看到项目被拆成几块、一块块点亮；左边能打开需求、合同和长出来的代码。觉得不对，还是跟右侧说——背后总包自己对照蓝图，用白话告诉你是施工漏了还是新需求。**改个字号这类小事**不必再走完整套 Demo。

## 1. 两条铁律（全程适用）

### 1.1 右侧唯一对话入口

| 用户看见什么 | 用户点什么 | 成功标准 |
| --- | --- | --- |
| 右侧始终是同一个聊天窗；没有「去找另一个 Agent」「换一个对话框」的压力 | 随便说需求、说「这里错了」、说「标题大一点」 | 系统在背后分流（总包自查 / 小改快通道 / 大改走完整旅程）；界面上仍像在跟同一个人说话 |
| 若需要看自查报告，中栏可打开「质疑」视口，但**入口仍从右侧进** | 右侧出现「帮我查一下」之类引导后确认即可 | 不要求用户自己判断找 Supervisor 还是 Worker |

- **现状已有**：右侧聊天壳、中栏四视口（Demo / 任务图 / 质疑 / 合同）能切换；质疑引擎、草案、保护审批卡后端已在。  
- **缺口**：右侧话术还没稳定自动分流到「质疑自查 / Fast Path / 标准八步」；用户仍可能感到要自己理解按钮和 Tab。

### 1.2 Fast Path（局部修补免强制 Demo）

| 什么算小事 | 用户看见什么 | 成功标准 |
| --- | --- | --- |
| 例如：把标题字号改大、改一句文案、调个颜色（单文件、不碰登录/支付等保护、不跑危险命令） | 右侧说完后，**不必**再强制：出文档 → 静态 Demo → 点「实施」→ 看整张拓扑 | 直接在可试玩环境里改完给你看；可一键撤销本轮；越权（改到第二份文件等）自动停住并升成标准审批 |
| 新模块 / 多页面 / 复杂交互 | 走完整八步（见下） | 不偷偷当小事放行 |

- **现状已有**：底层合同状态机已支持 Fast Path 合法流转与越界熔断字段；保护清单与撤销快照能力在。  
- **缺口**：「一句话改字号 → 自动判定小事并跳过 Demo」的**完整产品闭环**尚未按非技术用户走通验收；真改码还依赖可用施工适配器。

## 2. 标准八步（复杂功能 / 新模块）

下列每一步写三件事：**看见什么 / 点什么 / 怎样算成功**，并标现状。

### 步骤一：右侧聊天梳理需求

| 看见什么 | 点什么 | 成功标准 |
| --- | --- | --- |
| 右侧用白话追问你想要什么；聊到一段落后，左侧「规范/资产」里出现或更新需求说明 | 只用右侧打字；可点开左侧需求文件阅读 | 需求文档会跟着对话变；你不用手写技术规格 |

- **现状已有**：能连上工作台、右侧对话、按需「出草案」（含 DeepSeek 补全）；保护相关推荐/审批卡能出。  
- **缺口**：对话过程中需求文档**持续自动增删**、左侧高亮「正在更新」的完整体验未按旅程验收通过。

### 步骤二：静态 Demo 预览，再决定是否真开工

| 看见什么 | 点什么 | 成功标准 |
| --- | --- | --- |
| 中栏出现可点的假页面（静态 + 虚拟数据），不是最终真服务 | 不满意 → 继续右侧聊；满意 → 点「确认原型 / 实施真实项目代码」一类按钮 | Demo 和真实代码隔离（假页面碰不到你的密钥与主控端口）；确认前不会大面积真改仓库 |

- **现状已有**：Demo 生成与独立预览服务、中栏 Demo 视口壳、出草案按钮与中间区高度已修；走查能点到「出草案」。  
- **缺口**：「确认原型 → 一键开工」整条编排对非技术用户仍不顺手；Demo 与右侧补丁热更新的完整体验未走满。

### 步骤三：拆成功能块与任务顺序（Graph）

| 看见什么 | 点什么 | 成功标准 |
| --- | --- | --- |
| 中栏任务图：业务块像思维导图；下面是按顺序做的任务；一开始全是灰的 | 以查看为主；合同/需求/任务图可在左侧打开 | 复杂系统被拆成你看得懂的块；左侧能打开需求、合同等文档 |

- **现状已有**：任务图引擎与中栏 Graph 视口、左侧规范资产区能力已合入。  
- **缺口**：从「确认 Demo」自动生成并展示**本轮完整灰拓扑**的旅程级串联，仍需按本验收稿走通。

### 步骤四：真实施工，代码长出来，图被点亮

| 看见什么 | 点什么 | 成功标准 |
| --- | --- | --- |
| 左侧文件树陆续出现真实代码；中栏灰节点一块块变绿（做完才亮，不能假绿） | 一般不用手点施工细节；要停可点停止类控件 | 点亮必须有真写入 + 检查通过等硬证据，不是 AI 口头说「做完了」 |

- **现状已有**：点亮规则与证据校验、文件树刷新相关能力在规范与代码侧已有底座。  
- **缺口**：面向日常项目的**真施工适配**（如 CLI / 容器施工员）未齐；「看着代码长出来 + 拓扑逐个点亮」尚未达到可日常依赖。

### 步骤五：打开真实页面验收

| 看见什么 | 点什么 | 成功标准 |
| --- | --- | --- |
| 中栏或预览区打开**真实跑起来的页面**（不是步骤二的假 Demo） | 自己点点用用；没问题再确认一个版本 / 合入 | 主观试玩 + 客观检查都过，才允许安心定版 |

- **现状已有**：展示态里有「真实试玩」等状态投影能力；双门禁在规范中已定义。  
- **缺口**：走查结论仍是「壳子与门禁可试用」，**一键拉起真页面给人玩**的闭环未作为非技术验收通过。

### 步骤六：有问题 → 质疑（仍走右侧，背后总包自查）

| 看见什么 | 点什么 | 成功标准 |
| --- | --- | --- |
| 你在右侧说「这里做错了」；得到白话回复，例如：「方案里写了夜间模式，是施工漏了，我让它免费补」或「方案只约定了日间，这是新功能，要更新方案」 | **不要**被迫换一个「监工专用对话框」；需要时中栏打开质疑报告看对照 | 分清「施工漏做」vs「新需求」；漏做不擅自扩大改动范围；说不清时把三方事实摆给你选 |

- **现状已有**：质疑自查引擎、三方证据、中栏质疑视口接口已合入。  
- **缺口**：右侧自然语言 → 自动进入自查 → 白话归因回复的**统一入口体验**未验收通过。

### 步骤七：有新需求 → 仍在右侧聊，改旧文档

| 看见什么 | 点什么 | 成功标准 |
| --- | --- | --- |
| 需求文档在原有基础上增删（能看出哪版加了什么），不是每次从零撕掉 | 右侧继续聊即可 | 变更可追溯；与本轮变更编号对齐（背后有关联，你不必记技术 ID） |

- **现状已有**：需求快照 / 修订版本能力在质疑与规范资产侧已有。  
- **缺口**：增量增删标记对用户可读、并与对话连续联动的产品旅程未收口。

### 步骤八：在旧 Demo 上改一版 → 再确认 → 循环

| 看见什么 | 点什么 | 成功标准 |
| --- | --- | --- |
| 假页面在上一版上改，而不是完全重做一份陌生界面 | 满意再点实施；不满意继续右侧聊 | 回到步骤三/四循环；小改走 §1.2 Fast Path，不强制完整拓扑 |

- **现状已有**：Demo 快照与回退能力在服务侧已有。  
- **缺口**：「旧 Demo 打补丁 → 确认 → 再实施」对非技术用户的完整循环未走查通过。

## 3. 现在能试用 vs 还不能当日常副驾

**已经比较稳、可以点着玩的（壳与门禁）**

- 打开工作台、连上后台、四视口切换、中间内容区看得见  
- 出草案（规则草案 + 模型补全）、保护文件「同意 / 不同意」且不会自己消失  
- Demo / 任务图 / 质疑 / 合同的**视口壳**在  

**还不能承诺给非技术用户「开箱走完八步做一个真项目」的**

- 右侧唯一入口自动分流（质疑 / 小事 Fast Path / 大事标准八步）  
- 确认 Demo 后一键真开工、拓扑随任务点亮、真页面验收定版  
- 真施工适配器齐套；改字号级 Fast Path 产品闭环

## 4. 建议的实现顺序（先文档、后代码）

本页只定验收，不改产品代码。若继续做，建议按用户能感知的顺序收口：

1. 右侧统一承接（含质疑白话回）  
2. Fast Path 小事分流（免强制 Demo）  
3. 「确认原型 → 开工 → 点亮 → 真预览」主链  
4. 增量变更循环（旧文档 + 旧 Demo）  
5. UI 抛光（你此前说最后统一做）  

每收口一步，用本页对应表格再走查一遍：看见什么、点什么、是否达到成功标准。
