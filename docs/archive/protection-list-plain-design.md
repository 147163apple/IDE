> 依据：任务文档 v1.3.3 的 P.1 卡、架构文档 v1.3.3 §0.2 / §0.6（含本次新增 §0.6.5、§0.6.6）、`agent-claims-check.md`。
> 标注说明：写「验收要求」的，是要做到并测出来的，不代表现在已经做到；写「待设计/待验证」的，现在不承诺。

## 1. 一句话说清
**把「登录」「支付」这类地方锁上，AI 改别处你不用管。它要碰锁住的地方，会先停下来，用一张卡问你一次「同意吗」。改完、检查全绿以后，你点一次「合并」。一共最多两下。**

## 2. 三个场景

**场景 A：第一次打开项目**
Supervisor 按固定规则扫一遍项目（看文件夹和文件名，比如 `auth`、`login`、`payment`、`.env`），不调用 AI 模型，然后弹出推荐卡片：「发现【登录】相关代码，要锁住吗？」你点「全部锁定」，或者一张张选。以后可以在左栏「保护清单」里开关。

**场景 B：平常的一轮修改，然后撤销**
你说「把首页按钮改成蓝色」。AI 动手前，后台先存一份快照（只用来撤销）。全程不弹窗。觉得不对，就点顶栏「撤销本轮改动」，这轮涉及的文件回到开始前的样子。
- 注意：v0.1 的撤销是把整轮退回快照。这轮里你自己手改的部分**也会一起撤掉**，确认框会直说。「只撤 AI、留下你的手改」以后再做。

**场景 C：AI 想改锁住的登录文件**
AI 准备写 `src/auth/login.ts`，还没写进去就被拦下暂停，弹出**一张**卡，列出这轮要碰的所有受保护文件：
- 点 **「同意」**：这一轮里，AI 改卡上列出的这几个文件都不会再问你。只有它想改**清单以外**的锁住文件时，才会再弹一张「补充卡」。补充卡算作同一次授权的补充，仍在「最多 2 下」之内。锁本身不解开，下一轮还会重新问。
- 点 **「不同意」**：一个字都不写。AI 收到「这里被锁了，请换个办法」，继续做别的部分。
- **不点（走开、断网、电脑重启）**：一直等着，状态会存下来，回来后卡片还在，**永远不会自己放行**。
- AI 做完后，后台自动跑检查。检查全绿，顶栏出现「合并」，你点一次就进主线，**没有第二次确认**。

## 3. 界面长什么样

推荐卡片（首次导入）：
```
┌─────────────────────────────────────────┐
│ 🔒 建议锁住这些重要部分                    │
│  [✓] 登录（src/auth 等 6 个文件）           │
│  [✓] 支付（src/payment 等 3 个文件）        │
│  [✓] 密码和密钥（.env）                    │
│        [ 全部锁定 ]   [ 以后再说 ]          │
└─────────────────────────────────────────┘
```
顶栏（常驻）：
```
 1020 · main │ 🔓 自由模式 / 🔒 保护模式（已锁 3 处）│ [ ↶ 撤销本轮改动 ] [ 合并 ]
```
碰到锁时的卡片（一轮一张，列清单）：
```
┌─────────────────────────────────────────┐
│ AI 想修改被保护的代码，同意吗？              │
│ 这轮要改：                                 │
│   · src/auth/login.ts（改登录按钮文字）      │
│   · src/auth/session.ts（同步改提示）        │
│ 同意：本轮只放行上面这几个文件。             │
│ 不同意：这里一点不动，AI 换别的办法。         │
│          [ 同意 ]      [ 不同意 ]           │
└─────────────────────────────────────────┘
```
撤销确认：「回到这轮开始前的样子？这轮改过的 4 个文件会恢复，你这轮自己手改的部分也会一起撤掉。【撤销】【算了】」

## 4. 规则与验收要求（白话）
1. **自由模式 / 保护模式怎么定**：没锁任何东西 = 自由模式（没有合同门槛，但碰锁必问）；锁了 = 保护模式。不管哪种模式，碰到锁住的文件都按场景 C 处理。
2. **先拦后写**：AI 每次写、删、改名文件，都先过一道「门卫」，查固定规则，不问 AI 模型。
3. **门卫出错就拦（验收要求，未证明）**：出错、超时、没回应都算拒绝。要用测试证明 AI 走这四条路都绕不过去：它自带的改文件工具、命令行（Shell）、改名/删除、符号链接（「快捷方式」指向锁住的文件）。
4. **保护清单自己也锁着**：`.stagent/protection.json` 只能你在界面上改，AI 改不了。快照存不下来，这轮就不开工。
5. **三样东西别弄混**：快照 = 用来撤销；静默合同 = 后台记一笔「这轮打算改哪些范围」；证据（Evidence）= 只有保护模式走正式流程时才有，是合并的依据。普通自由模式的改动没有正式合同和证据。
6. **冲突听你的**：合并时你的版本和 AI 的打架，永远保留主线上你的版本，让 AI 基于最新代码重做。
7. **API Key**：所有模式都只用 API Key，不用官方账号登录。Key 由 Stagent 在启动 AI 时临时塞进去，**不写进**项目文件、配置文件、保护清单、日志和提交记录。
8. **Claude Code 的隔离启动**：**不用 `--bare`**（实测它会关掉我们的门卫钩子），改用官方参数组合（`--setting-sources ""` + 工具白名单 + 门卫钩子 + 独立配置目录）。已在 DeepSeek 兼容模式实测通过；用官方 Claude 再测一次列为后续回归项，不阻塞。详见 `claude-code-isolation-design.md`。

## 5. 不做的事 / 范围外
- 不让你手写路径规则；扫不出来的，可以手动点「锁住这个文件夹」。
- 锁只管写和删，不管读。
- 撤销只撤最近一轮。
- 防不了你在别的软件里直接改文件，也防不了没接入门卫的 AI 工具（显示「未受控」）。
- **AI 配置文件加锁**（`.claude/`、`.mcp.json`、`.cursor/`）：安全上有必要，但**不在这张 P.1 卡的验收范围内**。要做的话，得先更新任务卡。
- 成熟度打分、徽章：推迟到 v0.2+。

## 6. 已拍板（2026-10-20）
1. 同意 ≠ 合并：同意 = 动手前授权；检查全绿后再点一次「合并」，没有第二次确认。总共最多 2 下。
2. 多个锁住的文件合成一张卡问。
3. 撤销 = 整轮退回快照，你这轮的手改也会撤掉，确认框写明；只撤 AI 的细粒度撤销以后再做。
4. 同意一次，本轮清单内的文件都不再问；超出清单才弹补充卡，补充卡仍算在「最多 2 下」里。
5. 自由模式的说法统一为：「没有合同门槛，但碰锁必问」。

## 7. 验收时你自己怎么核查
1. 新建空项目，让 AI「新建 hello 页面再改个颜色」：**一个弹窗都没有**，顶栏显示「自由模式」。
2. 点「撤销本轮改动」：hello 页面的改动消失。
3. 打开有 `login` 文件夹的项目：弹推荐卡，点「全部锁定」，顶栏变「保护模式」。
4. 让 AI「把登录按钮改成红色，顺便改登录提示」：只弹**一张**卡，列出这几个文件。点「不同意」，用访达打开文件，确认没变。
5. 再说一遍，点「同意」：这一轮里不再弹卡。检查全绿后点一次「合并」，没有二次确认。
6. 卡片弹出时关掉页面、重启 Daemon，再打开：卡片还在，文件没被改。
7. 让 AI「把保护清单删掉」：被拦住，左栏开关不变。
8. （开发者做）弄崩门卫，再让 AI 用四种方式（自带工具、命令行、改名/删除、符号链接）改登录文件：全部被拦。
